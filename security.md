# Security Policy

ActionShellScript handles local input capture, script generation, file persistence, playback, and debugging. Security reports should focus on issues that could affect confidentiality, integrity, or availability of a user's local workstation, files, or scripts.

## Supported Versions

Security fixes are provided for the current release line and the active development branch. Older releases may be patched at the maintainers' discretion.

## Reporting a Vulnerability

Please do not open a public issue for a suspected security problem.

Instead, report it privately to the project maintainers using the repository's private security reporting channel or another direct maintainer contact method.

Include as much of the following as you can:

- A clear description of the issue
- The affected version or commit
- Steps to reproduce
- Expected behavior versus actual behavior
- Any logs, screenshots, crash traces, or sample files
- Whether the issue requires local access, a crafted script, or a malicious input file

## Response Expectations

We aim to acknowledge reports promptly, investigate the issue, and coordinate a fix before public disclosure when possible. If a vulnerability is confirmed, we will work with the reporter on safe remediation and disclosure timing.
